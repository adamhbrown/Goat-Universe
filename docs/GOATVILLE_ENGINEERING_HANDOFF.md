# GOATVILLE engineering handoff

Pope Henry I · October 15, 2026 · proposal and isolated utilities only

GOATVILLE guest play can progress independently of Supabase. Official member
entries, picks, results, championships, BAAS and GPI remain behind the authenticated
competition boundary. Do not connect a browser stamp to an official award.

## What is delivered

| Path | Purpose |
| --- | --- |
| `backend/goatville/protocol.mjs` | Strict attraction catalog, source-bound messages, per-run random session, version/sequence checks, deduplication and revocation |
| `backend/goatville/host.mjs` | On-demand sandboxed iframe; no same-origin, top-navigation, form or popup permission; no identity passed to games |
| `backend/goatville/demo.html` | Isolated integration harness, not a public attraction or an application route |
| `backend/goatville/challenge.html` | Minimal keyboard/touch fixture with restrictive CSP, no network API access |
| `backend/static-artifact.mjs` | Read-only export audit for private paths, recognizable credentials, external code/CSS patterns and size budgets |
| `backend/scripts/verify-goatville-browser.mjs` | Repeatable optional Chromium acceptance; currently blocked by unavailable browser |
| `backend/test/local-recovery.test.mjs` | Real local PostgreSQL-WASM snapshot/restore of competition records and access restrictions |

No existing server, migration, scoring rule, homepage, package manifest, lockfile
or workflow is changed. No provider resource is created. Nothing is served by
the application until an integration change is separately reviewed.

## Integration contract for Kodak and Tiffany

1. Keep developing on your existing creative branches. This branch is
   `work/pope-operation-goatville-20261015`, based on foundation `705009d`.
   The draft targets `codex/backend-foundations`, not `main`.
2. Copy/adapt the **reviewed** guest modules into the static public export after
   joint review. `backend/` is their development location, not a directory to
   publish wholesale. Choose their final public paths deliberately.
3. Put the guest shell and reviewed game files on a recreational static origin.
   Keep the authenticated member portal and private operations on a separate
   HTTPS origin. The current host accepts only game entry URLs on its own
   origin, with no query or fragment. Do not pass arbitrary user-provided URLs.
4. Mount one game on explicit visitor action. Destroy the returned handle when
   leaving/replacing the attraction. A frame title, visible close control,
   keyboard path and focus return belong in the host UI. Do not preload every
   attraction, autoplay sound or require motion/time-critical gestures.
5. Each game is a small reviewed static HTML file with external classic JS and
   CSS. The fixture uses a separate document so a strict parent CSP can remain
   intact; it does not require inline scripts or `unsafe-eval`. Opaque sandbox
   frames cannot normally load same-origin ES modules without CORS, so the
   fixture intentionally uses a classic child script.
6. Keep `sandbox="allow-scripts"`. Never add `allow-same-origin`, top navigation,
   popups or forms to make an attraction work. Serve the child CSP via response
   headers in production when hosting supports them; the fixture also has a meta
   CSP. Maintain a reviewed deployment checklist for those actual headers.
7. The parent sends a fresh initialization message on frame load. It contains
   only channel, per-run session, attraction/version and reduced-motion state.
   Completion messages have exactly these fields:

```json
{
  "channel": "goatville.guest.v1",
  "session": "32 lowercase hexadecimal characters generated by the host",
  "attraction": "catalog-id",
  "version": 1,
  "sequence": 1,
  "type": "achievement",
  "achievement": "catalog-declared-id"
}
```

The parent requires the exact iframe WindowProxy **and** opaque origin `null`,
the random session, matching version, increasing bounded sequence, declared
achievement and exact message shape. A `null` origin alone is never identity.
The initialization message uses `*` only because an opaque target cannot be
addressed by a normal origin. It carries no private data or competition authority.
The fixture's reply names the expected parent origin.

8. Render returned stamp text with `textContent`. Do not render game messages
   with `innerHTML`. Unknown fields, including score/BAAS/GPI, are rejected.
9. `createGuestJournal()` starts in memory. Acquire `window.localStorage` only
   after the visitor opts in. The demo permits clearing stamps and opting out.
   Stored records have a versioned schema, bounded size/count, no PII or tokens,
   and the literal verification value `local-unverified`. Corruption/quota/private
   mode falls back to memory. Opt-in is deliberately required again after reload.
10. Never call competition `/commands` or grant membership from guest messages.
    Do not automatically import a local passport into an authenticated award ledger.

## Future authenticated boundary

Use a separate persistence adapter behind the guest host interface. It should
send a minimal claim to a recreational API only after account opt-in; the API
must infer the actor from a validated session, reject client user IDs, validate
the attraction/version/claim schema, rate-limit before expensive work and enforce
idempotency and ownership. No direct browser writes to an official award table.

An in-browser session value is message routing, **not** anti-cheat proof. For any
valuable achievement, issue a short-lived server challenge, validate evidence
under the particular game's approved verifier, and record verifier/rules versions
and correction history. Offline stamps remain souvenirs unless an explicit
policy defines a separate verified process. BAAS/GPI conversions require CEO rules.

Keep gameplay persistence and traffic quotas separate from picks/scoring. A viral
guest attraction or a broken game should not consume the competition database's
connection pool. Prefer cached public read models and a queue for validated
recreational events. The authoritative competition database remains the system
of record; profile/public leaderboard data is derived and contains minimal PII.

## Abuse, privacy and performance limits

The fixture restricts parent DOM/storage capabilities and outbound connections,
but it is not a resource container: a hostile script can still waste CPU/memory
or spam messages. Only reviewed bundled games are supported. Adding arbitrary
third-party games requires a different threat review and dedicated origin.

The local protocol bounds accepted claims and history; it does not provide
server-side rate limits, bot resistance or proof of human play. A future API
needs shared gateway limits, request-size limits, per-account challenge limits,
expiry, replay protection, telemetry without tokens/PII, and abuse monitoring.

The exported harness is about 12 KB of uncompressed HTML/CSS/JS with no external
fonts, packages or media. Use system/self-hosted fonts, compressed immutable
assets and small images; lazy-load heavy video/audio and start it only on demand.
There is no service worker, tracking script or background polling in this slice.

Initial export guard budgets: 500 files, 12 MiB total, 256 KiB per code file,
512 KiB aggregate HTML/CSS/JS, 1 MiB per image/font, 4 MiB per media file, and
eight directory levels. These are conservative review triggers, not Core Web
Vitals results. The aggregate-code number is an upper bound across the export,
not a measured initial request waterfall.

The static scanner is defense in depth, not a complete secret detector or HTML/JS
parser. Arbitrary passwords, obfuscation, generated URLs and all dependency
behaviors cannot be proven safe by regex. Review assets and actual network/CSP
behavior separately. A pass does not authorize publishing.

```bash
node backend/scripts/audit-static-artifact.mjs backend/goatville
```

For manual local inspection only (loopback, not an external host):

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory backend/goatville
```

Open `http://127.0.0.1:8765/demo.html`. Serve this directory alone, not the
repository or a database directory. Shut down the server after inspection.

If Playwright and its Chromium binary are available:

```bash
node backend/scripts/verify-goatville-browser.mjs
```

For a runtime-provided Playwright installation, set `GOAT_PLAYWRIGHT_MODULE` to
its trusted absolute ESM module path. No dependency is added to this repository.
The script tests 390/1440 widths, reduced motion, keyboard completion, denial of
parent DOM/storage/network access, memory-only reload behavior, opt-in persistence,
clearing and teardown. Exit 2 means browser tooling is unavailable; it is not a pass.

real iPhone Safari/VoiceOver and slow networks, verify focus behavior inside the

## Reviewed attraction catalog hardening — October 15 follow-up

A separate, narrow review branch `work/pope-reviewed-attraction-catalog-20261015`
targets draft PR #17 and tightens the sandbox host:

- `backend/goatville/catalog.mjs` is the checked-in allowlist of approved
  attraction IDs, exact version, title, achievement names and document-relative
  HTML entry point. Only the isolated `integration-test` fixture is approved.
- `mountGuestGame()` rejects unknown attraction IDs, version/title/achievement
  changes, and every unreviewed same-origin HTML path, including lookalike
  filenames in other folders. Query strings, fragments, cross-origin URLs and
  non-HTTP(S) schemes remain forbidden.
- Resolve against the current guest host page so isolated staging deployments
  can use a path prefix; the entry path must still be an exact match.
- More test cases exercise bogus same-origin pages, forged catalog fields,
  postMessage teardown and path-prefixed static hosting.
- To introduce a production mini-game, explicitly add its reviewed descriptor to
  the source-controlled catalog in a dedicated PR, alongside the static files,
  threat model, accessibility checks and test cases. Never populate the catalog
  from URL parameters, localStorage or server responses to ordinary visitors.

The allowlist does not prove gameplay integrity or turn browser-issued stamps
into official achievements. Keep the independent, local-unverified guest boundary,
and do not merge or deploy without the CEO's explicit approval.
